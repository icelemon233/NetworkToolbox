# 原生场景安装器验证

2026-10-25，Windows 11 x64。本地修订对应 FanController 0.4.7、LanDrop 1.2.4、NetworkToolbox 0.2.3，使用 custom 文件名，保留既有安装包与历史发布。应用版本未增加，尚未发布到 GitHub。

## 实现

三款共用 Inno Setup 7.1.0 安装事务和 x86 原生 C++ 界面，应用载荷仍为 x64。界面由固定版本 Zig 0.15.2 编译，只导入 Windows 系统 DLL；不额外依赖 WebView2、Electron 或 .NET。

整窗日间/夜间业务场景、摘要首页、右侧设置抽屉、自绘顶部、安装中红色取消按钮和同组完成按钮均在实际安装包内。安装范围、路径、快捷方式、正常取消、真实进度与完成动作连接 Inno。没有自动启动应用的 Run 项；仅点击“打开应用”才启动，先释放维护锁。NetworkToolbox QA 禁用该启动入口。

普通打开先显示首页，所有用户模式在点击安装后交给原始 Inno 启动器提权。交接携带路径与快捷方式，用就绪事件和进程状态协调，父进程完成资源清理并返回子进程状态。Unicode 缓冲区使用 Windows 返回的字符数，带参数卸载记录按 Unicode 字符索引解析。

准备失败在左侧给出原因、重试、设置和详情入口；底层文件 I/O 的重试/取消仍保留 Inno 的系统对话框。取消安装使用同主题确认，默认继续。确认取消后显示撤销状态，Inno 清理新变更，升级恢复日志随后还原被替换的旧文件与安装记录。失败恢复目录会保留并提示位置。

## 自动验证

- `test-assets.ps1`：三款业务身份、原图和导出哈希、尺寸、日间/夜间文字区差异。
- `test.ps1`：当前用户首次安装、中文/空格路径、快捷方式组合、维护互斥、同位置升级、模拟旧 NSIS 登记迁移、路径拒绝、卸载记录清理、用户资料和安装目录内自放文件保留；另验证同名其他快捷方式在创建时拒绝覆盖，未勾选及卸载时保留。
- `test-custom.ps1`：真实原生 DLL 初始化并驱动安装；经同一交接协议重新启动当前用户安装，保留中文/空格路径、快捷方式与子进程退出码；安装完成；复制中取消新装；取消升级后恢复每个旧文件的哈希和卸载记录。旧 EXE 特意附加上一版本标记，避免用新旧文件相同的结果假装验证恢复。
- 原有 FanController 模拟宿主/服务覆盖恢复后退出、拒绝、超时、错误目录、静默拦截、托盘及旧名称窗口；LanDrop 已用真实打包程序和私有资料目录验证正常维护；这些既有结果见 inno-installer-validation.md，不将模拟风扇称为真实硬件验证。

交接自动测试使用当前用户模式，不接受 UAC。测试目录、注册项、互斥锁、快捷方式、数据和启动参数均私有；最新 QA 窗口和应用列表标有 QA。测试不修改日常安装、不安装共享运行库、不控制风扇或改网络配置。

## 可视验收与限制

真实 FanController 安装窗口中已观察到场景、进度与红色实心取消按钮；自动流程确认了三款真实界面初始化和状态衔接。Windows 防火墙的 Python 权限提示遮挡了后续鼠标操作，未代用户处理该提示，因此没有把预览图或自动流程当作完整鼠标、键盘和屏幕阅读器验收。

待独立实机确认：所有用户模式的实际 UAC 授权/拒绝、原始用户权限启动、缺少运行库的干净系统、Windows 10、100/125/150/200% DPI/文字缩放与跨屏、高对比度、真实辅助技术、风扇硬件恢复和 NetworkToolbox 实际网络任务退出。

## 成品与规范

本地包名分别为 FanController-v0.4.7-windows-x64-custom-setup.exe、LanDrop-v1.2.4-windows-x64-custom-setup.exe、NetworkToolbox-Setup-0.2.3-custom.exe。它们未签名；正式发布使用新版本。包旁的 .sha256 与 .build.json 记录引擎和 UI 编译器、DLL、公共源文件、场景清单、应用载荷及安装器许可文件摘要。

完整产品约定集中在 cinna-app-engineering 的 references/windows-installer.md，并从 cinna-windows-ui 路由；仓库内 installer/inno/README.md 说明实现、工具链和测试。旧 NSIS 位图尺寸不再作为当前界面基准。
