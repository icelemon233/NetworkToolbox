# 安装期间响应修复（2026-10-25）

本地 custom-r3 比较包：FanController 0.4.8、LanDrop 1.2.5、NetworkToolbox 0.2.4。

问题发生在实际安装期间。原实现的前台窗口和 Inno 事务共享消息线程，解压、系统查询或磁盘操作会阻塞按钮反馈；空闲首页及设置往返的绘制回归未覆盖这一点。

修复将安装事务交给独立的 Inno 后台进程，前台保留窗口与消息循环，以有界本地共享状态通道接收真实阶段和进度。取消、正常退出确认和错误都有明确的往返；后台结束并完成清理前不显示安装成功。原 Inno 文件写入、卸载日志、旧版迁移与恢复日志继续负责事务。原始用户、SYSTEM 与管理员可访问状态通道；随机名称、版本和大小固定，通道不接收命令或写入路径。前台退出时，后台通过取消标志和所属互斥锁停止事务，不结束后台进程。

后台使用 /SILENT /SUPPRESSMSGBOXES，其向导保持逻辑可见但为全透明、不激活的工具窗口，以调用 Inno 自身要求可聚焦窗口的正常取消路径。没有第二个可见安装界面。直接命令行的 /VERYSILENT 与 /CLOSEAPP 策略保持原样。右上角按钮的悬浮改为处理消息时立即绘制，不等待后续空闲绘制。

NetworkToolbox 相同载荷的本机前后测量：

| 指标 | 原实现 | 修复后 |
| --- | ---: | ---: |
| 最长消息派发延迟 | 6062 ms | 62 ms |
| 最长悬浮样式绘制延迟 | 6062 ms | 78 ms |
| 超过 100 ms 的绘制样本 | 4 | 0 |
| 已绘制样本 | 386 | 696 |

QA 测量向安装器自己的窗口投递消息，并走同一按钮绘制路径；不发送用户输入。它测量消息/控件绘制响应，不等于合成器呈现延迟或各类显示器的帧率认证。test-responsiveness.ps1 可保存结果并按明确的本机延迟预算校验。实机鼠标验证仍受当时前台独占应用影响，未把终态截图当作忙碌期间的指针验收。

自动回归覆盖新装、升级、前台发送取消后后台执行正常回滚、逐文件恢复旧版、资料保留、直接静默维护，以及 LanDrop 真实打包程序的前台正常退出确认/拒绝。测试编译时隔离目录、注册项、互斥锁、快捷方式和数据，未升级日常安装。

既有绘制修复继续保留：无渐变竖线，设置往返复用场景缓存并保持常驻控件，最小化中性悬浮与关闭危险红色。完整规范已同步 cinna-app-engineering 与 cinna-windows-ui。实际全机 UAC、其他系统和物理 DPI 的限制沿用既有验证记录。
